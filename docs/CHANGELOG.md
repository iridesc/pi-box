# 能力变更日志

给 agent 读。记录**能力层面**的变化，不是 commit 流水账。

用途：当有人问「pi-box 支持 X 吗」，先查这里，再查源码。这里的条目可能比你的记忆新。

格式：倒序。每条只说「多了什么能力 / 修了什么坑」，不写实现细节——细节去源码。

## 2026-11

### 输入框支持图片与文件

- **输入框从单行 `<input>` 换成 `<textarea>`**：`Enter` 发送、`Shift+Enter` 换行、自动增高（上限 200px）。中文输入法组合中的 Enter 不会误发。
- **三种添加方式**：粘贴（`Ctrl+V`）、拖拽（整个输入区可落）、点 📎 选择文件。一条消息最多 10 个附件。
- **图片进上下文，文件只给路径**：
  - 图片读回来经 `prepareImageBlocks()` 缩放/切片后内联成 `image` block，模型无需再 `read` 就能看到。
  - 其他文件只在文本里列「附件：<路径>（大小）」，模型自己决定 `read` 还是 `bash`。
- **附件落在 `<会话工作目录>/.pi-box/uploads/`**：文件名由后端生成（时间戳 + 随机 + 原名），前端不能指定路径。该目录在 `PROTECTED_HEADS` 里，删不掉，也不在文件树里显示。
- **会话记录里能看到附件**：图片显示缩略图（点击原图），其他显示文件名 + 大小。元信息存在 `entry.data.attachments`（`kind = app.user-attachments`），库里只存路径不存 base64。
- **可以只发附件不写字**：纯附件消息不再被前端的空内容检查拦掉。

相关参数：`PI_BOX_ATTACHMENT_MAX_BYTES`（默认 200MB）、`PI_BOX_ATTACHMENT_MAX_COUNT`（默认 10）、`PI_BOX_ATTACHMENT_MAX_IMAGES`（默认 6）。

相关端点：`POST /api/attachments/upload`、`GET /api/attachments/preview`、`POST /api/attachments/delete`。

### 报告阅读页修复

- **点报告组的「打开箭头」不再白屏**。`/reports?project=&group=&stamp=` 之前被报告页面路由抢走了，返回的是公开页 `public.html`，而它只认 `/r/<slug>` 这种路径，于是拿到页面却渲染不出东西。现在 `/reports` 交回主应用（app.js 里有独立的阅读视图），公开页只管 `/r/*`。
- **公开页支持跳任意一份**。之前只有 `‹ ›` 前后翻，跳不到中间某份。现在点期号（`1/3`）展开列表，样式和内侧的 FAB 面板一致，键盘 `←` `→` 仍然可用，`Esc` 收起。

### 长图切片按组淘汰

- 上下文裁剪从「按单张图」改成「按组」：一条消息里的图要么全在、要么整组消失。
- 修的问题：一张长图切成 7 片放在同一条 toolResult 里，按单张淘汰会出现「只剩第 4-7 片」；更糟的是末尾那段「已切成 7 片，纵向范围 1..7」的说明不会被裁（它不是图片），于是模型看到说明说有 7 片、实际只有 4 片，比单纯缺图更容易错位。现在整组被淘汰时，那段说明一起换成占位。
- 最新一组**保底保留**，哪怕它自己就超过 target —— 否则刚读完的长图会当场被裁光，等于白读。代价是请求体可能超预算，所以超限时打日志提示「先用 bash 裁区域或转文本」。
- 组内**不互相去重**：长图里连续的空白片内容相同，合并会让「第几片」的片号全部错位。
- 内容去重只在**跨组**生效（同一张长图读两次 → 旧的那 7 片整组丢掉，新的 7 片留着）。
- 存储级 `stripImagesFromRecords` 同样按组，但不保底（离线清理的目标就是压体积）。

### 视觉输入统一入口

- 切片逻辑抽成 `prepareImageBlocks()`：给字节 + 模型限制，返回「进上下文时该长什么样」。
- 现在只有 `read` 工具在调。将来用户贴图/上传附件必须调同一个函数，否则两条路径切出来的字节不同，内容哈希对不上、去重会失效。

### 图片去重改用内容哈希

- 上下文里的重复图按**内容 sha256**判定，不再按文件路径。
- 修的问题是：同一个文件被改过之后，路径没变但内容已经换了，旧版本会被当成「重复副本」丢掉，模型看不到改动前的样子。现在内容不同就是两张图，都留着。
- 反过来也成立：用户反复贴同一张图、或把同一张图存成两个文件名，字节相同就合并成一份，只留最新位置。
- 用户直接贴进消息的图（没有文件路径）现在也能去重了 —— 以前这类图完全没有去重键。
- 成本用「长度预分桶」压掉：base64 长度唯一确定字节数，长度只出现一次的图不可能重复，连哈希都不用算。全量算一遍 24MB 约 26ms。
- 历史库不做全量扫描修复；`scripts/strip-images.mjs --dedupe` 的判定同步改成按内容。

### 上下文占用与压缩

- **会话顶部显示上下文占用**：`上下文 12% · 15k / 128k · 图 3 张 2.1MB · 812 条消息`。token 优先用模型最近一次请求上报的实测值，没有实测才退回估算；图片单独给张数和字节数（token 估算里一张图恒为 4800 chars，看不见真实体积）。图片超过请求级预算时会显示成 `图 309 张 232MB → 本轮 7.8MB`，也就是「历史里存了多少」和「这一轮真的发多少」的区别。80% 起变黄、95% 起变红并给「压缩上下文（建议）」。
- **压缩只有手动这一条路**：`pi-durable` 的自动压缩（阈值压缩 + 溢出恢复压缩）在 pi-box 里被关掉了（`settings.compaction.enabled = false`）。上下文真的超限时请求会直接报错，由用户决定要不要压——不会悄悄改历史。
- 会话顶部的「压缩上下文」按钮 = `conversation.compact()`：把早期历史摘要成一段文字，原始记录仍保留在页面历史里（只是不再发给模型）。压缩时保留最近多少上下文由 `PI_BOX_COMPACT_KEEP_TOKENS` 决定（默认 8000，durable 默认 20000）；上下文比这个值还短时会直接提示「没有可压缩的内容」。压缩期间按钮显示「压缩中…」，摘要落地后自动刷新占用。
- **看到 `[图片已移除…]` 与压缩是两回事**：前者是图片字节预算（每次请求临时裁剪，不动历史），后者是把早期历史换成摘要条目（durable 记录的 CompactionEntry）。

### 图片与上下文体积

- **图片进上下文前会按模型尺寸上限缩放**。`read` 读图不再把原图 base64 原样塞进历史，而是按模型目录里的 `inputLimits.images.resize` 缩放重编码；PNG 源优先保留 PNG（截图文字不糊），照片才转 JPEG。`read` 的诊断行会写 `Resized from A×B to C×D. Multiply coordinates by N`，坐标换算照此进行。
- **历史图片的去重 + 字节预算**。图片在会话历史里以 base64 存着，**每一轮请求都会把全部历史图片重发一遍**；长会话能把请求体堆到几十 MB，直接撞网关的 body 上限（`413` / `payload too large` / `550`），表现却像网络故障。每次请求前现在有两道处理：
  1. **同文件去重**：同一个文件读过多次时，只保留最新那份图，旧副本换成「更新副本在后面」的占位。想读可以一直读，只是不会在上下文里堆副本。
  2. **字节预算**：去重后仍超阈值（默认 24MB）就从最老的不同文件开始换成占位，降到目标（默认 16MB）。阈值可用 `PI_BOX_IMAGE_TRIGGER_MB` / `PI_BOX_IMAGE_TARGET_MB` 覆盖；这两个默认值按实测校准（同一网关 26.8MB 能过、48MB 被拒）。
- **别反复读同一张图**。系统提示词里写明了：图片随工具结果以附件返回，读到就能看见，不需要"再读一次确认"；历史里见到 `[图片已移除以缩小请求体…]` 说明被预算裁掉了（需要再看就 read 一次），见到 `[同一文件 … 的更新副本在后面…]` 说明后面有更新的副本。实测有会话因为反复读同一批图读了 310 次（实际只有 39 个文件）。
- **长图自动切片**。整页截图这类又长又窄的图（高宽比 > 2.5，或长边 > 3000）不再被缩进 2000×2000 的方框压成一条细线，而是按原始分辨率自上而下切成多片返回：片高 1600px、相邻重叠 120px、最多 12 片。片宽保持原样，所以文字是可读的（1280×9533 之前被压成 269×2000，现在 7 片各 1280×1600）。返回时带一段说明，写明片数、重叠和每片的纵向范围，模型按片读即可；超过 12 片的图会退化成整图并明确提示"先裁区域或转文本"。普通图片、非图片文件、纯文本模型都原样走原来的 read，行为不变。
- **存量数据可离线剥离/去重**：`scripts/strip-images.mjs`（随镜像发布）。默认只预演，`--apply` 才写库（写前自动备份、写完 VACUUM）。两种策略可单用可合并：`--dedupe` 只删同一文件的重复副本（不同文件全留），`--keep-mb N` 按体积保留最近 N MB。必须在 pi-boxd 停止时运行。

### 完成提醒

- **agent 回复完成后会提醒**。设置 → 系统 → 偏好 → 完成提醒，三档：关闭 / 页面在后台时（默认）/ 总是。
- 用系统通知（Notification API），正文是 agent 最后一条回复的开头 120 字；点通知直接跳到那个会话。同一会话重复完成只保留一条，不会堆一屏。
- **系统通知只在 HTTPS 或 localhost 下可用**。内网 `http://<ip>:<port>` 属于非安全上下文，浏览器禁用该 API；这种情况下自动退化成「标签页标题前加未读数 `(3)`」，点开会话后消失。
- 定时任务的独立会话跑完不提醒（结果本来就不回流给助理/用户）。

### 实时连接

- **SSE 不会再「假死」**。原来事件流只在快照变化时写数据、没有心跳，遇到 TCP 半开或反向代理空闲超时，连接看着还开着其实早断了，表现是「页面不动了，刷新才有结果」。现在：服务端每 15 秒一次心跳、快照出错降级成注释而不是 `event: error`、连续失败 5 次主动断开让客户端重连；前端 25 秒收不到数据就自己重建连接，断线按 1/2/5/10 秒退避重试，页面回到前台或网络恢复时也会检查一次。
- **右上角连接指示器可点击手动重连**，悬停能看到重连原因。
- **当前会话的内容刷新不再依赖事件流**：只要选中会话在跑，就按 500ms 独立轮询，事件流断了也照样能看到进展。

### 文件管理

- **文件树每行带上操作**：目录行有 `⬆ 上传`、`＋ 新建文件夹`、`✕ 删除`；文件行有 `⬇ 下载`、`✕ 删除`。面板头那个统一的上传按钮取消了。
- **上传有目标目录**：点哪一层的 `⬆` 就传到哪一层；顶部「（项目根目录）」那行管根目录。上传过程在该行显示 `1/2 43%` 和一条进度条。
- **拖拽上传**：把文件拖到某个目录行上放手，直接传到那一层（拖拽时该行高亮）。
- **新建文件夹**：`＋` 在该层插入输入框，回车创建，Esc 取消。
- **重命名**：双击文件或目录名进入行内编辑，回车生效（双击后默认只选中主文件名，扩展名保留）。目录改名会带着展开状态和选中路径一起挪。
- **删除**：文件和目录都能删，目录是递归删；删除前弹确认框。`.git` / `.pi` / `.pi-box` 三个目录不给删（行尾不显示 ✕，后端也拒绝）。
- **预览刷新按钮不再依赖选中文件**：没选文件时刷新当前目录。

### 界面

- **项目设置改成弹窗**。原来占满第三栏，现在弹窗内完成改名 / 删除 / 子 Agent 管理 / 定时任务。第三栏不再被占用。
- **子 Agent 管理收进项目设置**。左栏不再有「子 Agent」标签和 ＋ 按钮，只留一条分割线。
- **报告入口改为左栏节点**。左栏「📊 报告」→ 第二栏组列表 → 第三栏详情，和「助理 / 文件」同构。不再是四级树。
- **弹窗尺寸全部放大一档**。基础 640、助理设置 820、项目设置 880、报告组 660、图标选择器 470，最大高度 92vh。

### 图标

- **项目 / 助理 / 子 Agent 的图标可以自定义**（emoji）。
  - 项目图标存 `<项目>/.pi/project.json`，助理和 Agent 图标存各自 `.md` 的 frontmatter `icon` 字段。
  - 内置 66 个 emoji 可选；未设置时用默认值（项目 📁、助理 🤖、子 Agent 🤖）。
  - 元项目图标锁定不可改。
  - 文件树里的文件图标固定，不参与自定义。

### 报告

- **报告组（Report Group）**。agent 通过 `report_publish` / `report_list` / `report_read` / `report_delete` 四个工具发布报告。
  - 报告落在 `<项目>/.pi/reports/<组名>/`，每次发布是一个独立完整的文档（时间戳命名），**没有版本链**。
  - 前端有全屏阅读页，支持 ←→ 切换、Esc 关闭、预取相邻。
  - HTML 报告必须单文件自包含，外链脚本/样式/图片一律拒绝。
  - **公开链接**：组可以设为公开，得到 `/r/<slug>` 稳定 URL，可分享给外部。
  - 公开后新发布的报告自动公开。
  - **可见性只能由人在界面上操作**，agent 没有设置可见性的工具。
  - agent 必须在其 frontmatter 里绑定 `reports: [组名]` 才能发布到该组。
  - 报告内容在 iframe sandbox 中渲染，CSP 关闭一切网络请求。

### 文件

- **项目文件浏览**。可以列目录、预览文本与代码（带高亮）、下载原文件、上传。
  - 只允许访问项目根目录内部，挡掉了 `..` 和符号链接越界。
  - 「文件」入口图标是 🗄️。

### 性能

- **SSE 增量渲染**。长会话不再整段重绘，单次处理从约 367ms 降到约 8ms。
- **静态资源 gzip + ETag**。首屏要下载的资源从约 339KB 降下来，支持 304 协商。
- **首屏快照瘦身**。`/api/state` 响应体积下降约 90%，首屏从约 9.6s 降到约 4.5s。

### 定时任务

- **支持三种执行方式**：纯命令、纯 LLM、命令 + LLM。
  - 纯命令任务没有 LLM，**没法写报告**。要写报告就用「命令 + LLM」：命令把结果写文件，LLM 段读文件再总结。
  - 命令的 stdout 只保留尾部 16000 字符，提示词模板只用其中 4000，数据量大必须走文件。
- **修复 cron 任务永不自动触发**的问题。
- `{{stdout}}` 只取 stdout，stderr 单独进日志。

### 其他

- 系统设置里可以自定义页面标题和标签页图标。
- 内置 msg-hub 消息渠道 MCP（构建期拉取）。

## 维护约定

- 每次发版在这里加一条，写「能力」，不写「文件改了哪几行」。
- 如果某项能力被移除或行为变了，在对应条目下写「已变更：」，不要直接删掉旧条目。
- **不写任何部署信息、主机地址、账号、密钥、内部域名。** 这份文件会进镜像，agent 能读到。
